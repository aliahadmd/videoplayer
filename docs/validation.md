# Validation

The authoritative playback result is [playback.json](validation/playback.json), generated by `python3 scripts/verify.py`. It records individual checks; a missing report or `success: false` is not a passing run. Model tests run with `swift test`.

The generated corpus covers H.264/AAC MP4, multi-audio MKV with ASS, external ASS/SRT, VP9, AV1, HEVC 10-bit PQ-tagged input, FLAC, corrupt input, and HTTP range playback. The final release also played a trusted Blender HTTPS trailer and rejected a loopback self-signed TLS certificate. These samples do not prove every codec/profile/container or network protocol combination. RTSP/RTMP are accepted engine protocols but were not exercised against live servers.

Native UI inspection uses accessibility and screenshots: rendered video/subtitles, seeking, inspector navigation, subtitle timing, single-dispatch shortcuts, file-open navigation, text entry, settings, full screen and quitting. Final results are recorded in the completion audit.

The dependency bundle is arm64/macOS 27.2. Native HDR output, system PiP, protected streaming services and public notarization are outside this local release. Bluetooth and physical multi-display behavior need the relevant hardware. No battery-life advantage is claimed.

Runtime checks caught integer-property formatting, asynchronous seek/screenshot completion, stale play-state/device caches, duplicate key dispatch, and termination-reply starvation. The real QA process and generated fixtures provide the regression loop.
